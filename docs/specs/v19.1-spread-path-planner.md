# Siegeline v19.1 spec: Spread + Path planner

Oct 21, 2026 · @Jerry

Built as v20.1 on top of v20 (which already contains the v19 code this spec refers to); see `CLAUDE.md`, history, v20.1.

## What's wrong now and what changes

The v19 scrubber puts each group's release track on a 60 s scale, so 40 s of every track is dead space, and groups can only be placed by dragging small dots on the map. v19.1 splits planning into two controls per group: a spread track for how the group comes out (0–20 s), and a path slider for where the group is on the route at the paused moment.

* Build on `bridges`, on top of the current v19 code. Label v19.1. Add an entry to `CLAUDE.md`.
* No protocol bump: only the existing timeline values (`tl.s`, `tl.e`, `tl.pos`, sapper launch times) are sent online, through `makeAtkPlan` as now.
* Use the numbers given here. Any choice this spec doesn't make goes in a "Decisions made in the build" list in the `CLAUDE.md` entry.
* Don't change any balance number.

## The controls

The Wave step has one master time slider at the top, then one row per design and per sapper. Each row has a spread track and a path slider.

### 1. Master time slider (keep)

* 0 to `RULES.planMax` (60 s), 0.1 s steps, play/pause, label "T = 10.0 s". Same as v19.
* It only picks the moment being previewed. It is the only control on a 60 s scale.

### 2. Spread track (restore to 0–20 s)

* Spans exactly the 20 s release window, as it did before v19. Its left edge is 0 s and its right edge is 20 s.
* The group's release band shows start (`tl.s`) and end (`tl.e`). Stretching or squeezing the band changes the spread, which is how bunched or strung out the group is.
* Changing the spread keeps the front unit's release time fixed and moves the end. If that would push the end past 20 s, stop at 20 s.
* The band can still be slid left or right directly. That moves its release time, same as a path drag does.
* Custom dot positions (`tl.pos`) keep working inside the band as now.

### 3. Path slider (new)

* A horizontal bar that represents the route, not time. Left end = entry tile, right end = keep. Its length = the route's length in cells at time T.
* Every row's path slider uses the same scale, stacked directly under each other, so lining up groups means lining them up vertically.
* At time T, the group shows as a band on its path slider. The band runs from the rear unit's route distance to the front unit's. Each unit is a tick inside the band.
* The band's length comes from the spread and the unit speed: a fast group with the same spread takes up more of the route than a slow one. Don't compute it separately; read it from the ghost wave (v19, Part C).
* Units not yet released at T show as a stub at the left end, labelled "+3 waiting". Units that have reached the keep stack at the right end, labelled "×4 at keep".
* Markings on every path slider: planned bridge tiles as a small bridge icon, and stretches of route inside any seen tower's range lightly shaded. Both come from `S.seenGrid` and the planned sabotage.
* Sappers get a path slider too, with a single tick.

## How a path drag sets the release time

The attacker drags the whole band along the path slider. The game works out when the group must start releasing so that it is exactly there at time T, with its spread unchanged.

1. Pause at any T. Grab anywhere on a group's band and drag left or right.
2. Read the front unit's route distance D from the drop position. The front unit is the first one released.
3. From the ghost wave, find `walk(D)` = how long that unit takes to walk from the entry to D.
4. New front release time = T − `walk(D)`. Shift `tl.s`, `tl.e` and every `tl.pos` entry by the same amount (seconds ÷ 20 for the 0–1 scale). Spread never changes during a path drag.
5. While dragging, move the band by shifting the recorded samples in time. On release, rerun the ghost wave once.

## Limits and edge cases

* Release window: the front can't release before 0 s and the rear can't release after 20 s. At a limit the band stops and a toast says "Can't release before 0 s" or "Must be released by 20 s". This is why a group can't reach every spot at every T; that is correct.
* Partly released groups: if some units are still waiting at T, dragging moves only the released part visibly, but the timing still shifts the whole group by the same amount.
* Drag to the left end: means "front releases at T". The band disappears into the waiting stub.
* Drag to the right end: the front reaches the keep exactly at T.
* Bridges: the path slider uses the route at time T, in whichever mode the v19 bridge toggle (Lands / Fails) is set to. If a bridge lands mid-wave, the route length and the markings change as the master slider passes that moment. After release, keep the new times even if the bridge timing moves the group slightly; don't re-solve.
* Frost: not previewed. Frost slows units in the real wave, so groups will arrive later than planned. Keep the existing board label warning about this.
* Most recent drag wins. Dragging a group at T = 15 s can undo what you set at T = 10 s. Keep the 1 s fading ghost of previous positions from v19, on both the map and the path slider.
* Groups are independent. Dragging one never moves another.

## Removals, tests and what stays

### Remove

* Dragging ghost dots on the map. The map still shows them at time T, but it's display only. All placement happens on the path sliders.
* "Align here", if it's still in the build. Lining up path-slider bands does the same job with more control.
* The 60 s scale on the per-group tracks.

Keep as in v19: the ghost wave, the master slider and play button, the bridge toggle, the board warning label, and everything about tower accuracy.

### Tests (`tools/tests/test_local.py`)

1. The spread track spans 0–20 s; changing the spread keeps the front release time fixed.
2. A path drag at T = 10 s puts the front unit within 0.2 cells of the drop point (no bridge planned) and leaves `tl.e − tl.s` unchanged.
3. With the same spread, a fast design's band on the path slider is longer than a slow design's.
4. Drags past 0 s or 20 s release stop at the limit and show the toast.
5. All path sliders share one scale: the same route distance sits at the same x position on every row.
6. Dragging on the map does nothing.
